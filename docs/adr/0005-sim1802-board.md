# 0005 — The sim1802 virtual board: reset, memory profiles, devices

Status: **Proposed — needs Alan's acceptance (Step 03 exit criterion)**
Date: 2026-09-29
Step: step-03

## Context

NuttX needs a board: memory map, reset path, console, tick and a way to end
automated tests. The simulator (ADR 0003 fork) has 64 KiB of RAM, an I/O
controller on ports 6/7, and an ELF loader that (upstream) jumps to any
entry point through a small bootstrap at address 0. The contract asks for
two memory profiles (SIM64 and HW32/32) and says the board layer should stay
clean enough for real hardware later.

## Options considered

1. **RAM-only image, loaded anywhere; the simulator's bootstrap jumps to it.**
   Simplest, but it models no real board: there is no reset code, `.data`
   never needs copying, and there is no ROM. HW32/32 could only be estimated
   from sizes, never run.
2. **ROM-at-0 board**: the image *is* the ROM, the reset code is at 0x0000
   exactly as on real hardware [MPM p. 72], `.data` is copied from ROM to RAM,
   and ROM is write-protected by the simulator. Two linker scripts give the
   two profiles.
3. As 2, but with one linker script parameterised by symbols. This is harder
   to read for a course, and the profiles differ in structure (copy vs no
   copy), not only in numbers.

Tick clock: express the tick in machine cycles directly, or define a nominal
CPU clock and derive cycles from `CONFIG_USEC_PER_TICK`.

## Decision

Option 2, as documented in [`docs/cdp1802/board-sim1802.md`](../cdp1802/board-sim1802.md):

- reset at 0x0000: `DIS` with inline byte 0x00, then switch the PC to R3 (R0 is
  freed because the board has no DMA);
- **HW32/32**: ROM 0x0000–0x7FFF, RAM 0x8000–0xFFFF, `.data` copied, whole
  ROM write-protected. This is the profile used for feasibility judgements;
- **SIM64**: read-only image from 0, RAM directly after it up to 0xFFFF,
  `.data` in place, read-only part write-protected;
- loadable bytes end below 0xFF00 (simulator loader limit), asserted in both
  linker scripts;
- devices: the fork's console (IRQ 6), cycle-driven timer (IRQ 0), cycle
  counter and HALT, all through ports 6/7;
- a nominal CPU clock `CONFIG_BOARD_SIM1802_CLOCK_HZ`, default 4 MHz (MPM's
  example clock), used to turn `CONFIG_USEC_PER_TICK` into a timer period;
  the default tick is chosen in Step 07 from measured interrupt cost.

Two simulator changes were needed and are in the fork: ELF segments are
loaded at `p_paddr` (commit `1be386b`, otherwise the ROM copy of `.data` was
never loaded, found by the smoke test printing a garbage tick count), and
`__sim1802_rom_end` sets the write-protect limit (commit `bef5700`).

## Consequences

- The start-up code (Step 06) is the same as a real ROM board's: it copies
  `.data`, clears `.bss` and initialises the NCRT registers.
- HW32/32 is *executable*, not just a size estimate: an image that does not
  fit fails to link (linker `ASSERT`), and a stray write into ROM stops the
  simulator with status 97.
- `smoke.S` + `sim64.ld`/`hw32.ld` are the prototypes for the NuttX linker
  scripts in `boards/cosmac/cdp1802/sim1802/scripts/` (Step 05).
- Only the board layer knows about ports 6/7; a real board replaces those
  drivers (see §5 of the board document).

## How to revisit

A different RAM/ROM split (e.g. 16/48) is a new linker script and a new
profile row in the size budget, with no code change. If NSH does not fit in
HW32/32 (Step 10), a banked profile would need a new ADR.
